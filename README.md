# Cortical-Model-Tutorial — developer and maintainer guide

This repository is a hands-on tutorial for a **multi-area spiking network model of one human
cerebral hemisphere**: the Human Multi-Area Model (HuMAM, Pronold et al. 2024) run in NEST 3.8,
extended with custom neuron types (amyloid-beta pathology) and an analysis toolbox that ends in
LFP-, BOLD- and FC-like signals.

**This README is for the people who develop and maintain the tutorial.** Participants never need
it: everything they do - installing, running, reading - is in `Cortical_Model_Tutorial.ipynb`
(Part 0 covers the environment). Here you find how the repository is put together, which results
are generated by what, how to regenerate them, and what is known to be wrong.

At full scale the model has 3.47 M neurons and 42.8 G synapses. The notebook runs it downscaled
(`N_scaling = 0.01`, `K_scaling = 0.1`) on a laptop and shows three full-scale runs computed on a
server as pre-rendered figures.

## 2. Design rules

Keep these when you change anything; the notebook text relies on them.

- **Nothing writes into `model/`.** Every output goes to `results/`. The stages run with
  `cwd = model/` because the model builds its data paths from `os.getcwd()`; `run_stage` sets it.
- **An experiment is three dictionaries** - `net_params`, `sim_params`, `ana_params` - in a plain,
  side-effect-free file. Each stage reads the file again, and each stage's output directory is the
  hash of its own dictionary: `results/<run>/<net_hash>/<sim_hash>/<ana_hash>/`.
- **No reuse on the laptop.** `run_all(experiment)` deletes `results/<run>/`, writes a driver
  `results/<run>/experiment.py` that points the output there, and runs all three stages. Reuse of
  finished stages exists only in the server's Snakemake workflow (notebook 6.1).
- **Overrides are merged by `helpers/snakemake.py:nested_dict_update`.** A value must have the
  type of the default it replaces - `int` and `float` are interchangeable when no information is
  lost, a dict for a default that is not a dict raises `TypeError` - and a key whose default is
  missing or `None` takes any value. It *replaces* `neuron_params_X` / `neuron_param_dist_X` as a
  whole; custom neuron types (`neuron_types`) instead inherit every parameter they leave out.
- **`tutorial_amyloid.py` differs from `tutorial_CN.py` only in its neuron type and its own
  full-scale rates.** It reads `eta_ext` and `t_sim` from `tutorial_CN.py` so the two cannot drift
  apart; recalibrate the healthy experiment, never the pathological one.
- **The notebook is distributed with outputs.** Outputs must come from one top-to-bottom run of the
  committed code and data (section 5.2), with personal paths replaced.

## 3. Environment

```bash
mamba env create -f environment.yaml        # creates the env "nest3.8": NEST 3.8, Python 3.12, pinned stack
mamba activate nest3.8
python -m ipykernel install --user --name nest3.8 --display-name "nest3.8"
```

The notebook's metadata names the kernel `nest3.8`. Everything that imports NEST - the three
stages, both calibration tools, executing the notebook - must run in this environment. Keep
**pandas 2.2**, the pinned version: network construction also runs under pandas 3 (same network
hashes), the rest of the pipeline has not been tested there.

Hardware the participants are told about (notebook 0.3, 2.2): 4+ cores, 8 GB RAM minimum,
16 GB recommended, ~8 GB free disk; macOS, Linux, or WSL2 on Windows (NEST has no native Windows
build).

| `N_scaling` (`K_scaling` = 0.1) | Neurons | Internal synapses | Peak RAM |
|---|---|---|---|
| 0.002 | 6.9 k | 8.6 M | 1.3 GB measured |
| 0.005 | 17 k | 21 M | 3.1 GB measured |
| **0.01** (default) | 34.7 k | 42.8 M | ~5.9 GB predicted |
| 0.02 | 69 k | 86 M | ~10.6 GB predicted |

Predicted values use the rule `0.4 GB + 128 B x synapses` (notebook 0.3); NEST reports no
memory on macOS, so the default size has no measurement.

## 5. Maintenance procedures

### 5.1 Recalibrating after a change of `net_params`

Needed whenever the drive, the weights or gains, the anatomy (connectome, cytoarchitecture), the
neuron parameters or the neuron types of an experiment change. The DC current that replaces ~70 %
of the mean input of a downscaled network is computed from the experiment's full-scale rates, and
those rates depend on all of these.

```bash
# 1. scan the drive of the healthy experiment (one seed is enough for a first pass)
python tools/eta_ext_search.py --experiment experiments/tutorial_CN.py \
    --method scan --eta-list 4.5 5.0 5.5 --threads 8 \
    --outdir results/calibration/tutorial_CN/eta_search
#    --fullscale-rates <file> uses a newer rate estimate than the experiment's own

# 2. full-scale rates at the chosen drive, for the healthy and the pathological experiment
python tools/fullscale_rates.py experiments/tutorial_CN.py --iters 40 --threads 8 \
    --workdir results/calibration/tutorial_CN/fullscale_rates \
    --out results/calibration/tutorial_CN/fullscale_rates_eta5.pkl
python tools/fullscale_rates.py experiments/tutorial_amyloid.py --iters 40 --threads 8 \
    --workdir results/calibration/tutorial_amyloid/fullscale_rates \
    --out results/calibration/tutorial_amyloid/fullscale_rates_eta5.pkl

# 3. install them
cp results/calibration/tutorial_CN/fullscale_rates_eta5.pkl experiments/fullscale_rates/tutorial_CN.pkl
cp results/calibration/tutorial_amyloid/fullscale_rates_eta5.pkl experiments/fullscale_rates/tutorial_amyloid.pkl
```

- Without `--start`, `fullscale_rates.py` starts from `model/simulated_data/base_theory_rates.pkl`,
  which belongs to `eta_ext` 1.1 with the old gains 1.0 / 2.0 - far from the tutorial's state.
  To continue an interrupted or earlier run, pass `--start <workdir>/rates/eta<eta>_it<n>.pkl`
  (the input of iteration `n`, written at its start); `--out` is written only at the end.
- Converged means the mean |step| per iteration (the `dE`, `dI` columns of
  `<workdir>/iterations.csv`) has levelled off at the finite-size noise, about 0.05 Hz (E) and
  0.06 Hz (I) at this size. From `base_theory_rates.pkl` that takes 25-40 iterations.
- `fullscale_rates.py` refuses `--eta` for an experiment with `neuron_types`: the pathological
  experiment is iterated at the drive it inherits from its healthy control.
- If step 1 picks another `eta_ext`, set it in `tutorial_CN.py`, then run step 2 at that drive and
  scan once more with the new rates file.
- Afterwards update the comment above `"input_params"` in `tutorial_CN.py` (scan values, rate
  means, iteration count) and section 4 of this README.

### 5.2 Re-running the notebook and refreshing its text

```bash
mamba activate nest3.8
jupyter nbconvert --to notebook --execute --inplace \
    --ExecutePreprocessor.kernel_name=nest3.8 --ExecutePreprocessor.timeout=-1 \
    Cortical_Model_Tutorial.ipynb
# personal paths: check_environment() and print_excerpt() print absolute paths
python -c "import pathlib as p; f = p.Path('Cortical_Model_Tutorial.ipynb'); \
f.write_text(f.read_text().replace(str(p.Path.cwd()), '/path/to/repo'))"
grep -c "$HOME" Cortical_Model_Tutorial.ipynb      # must print 0
```

This deletes and rebuilds `results/tutorial_CN/`, `results/tutorial_amyloid/` and the four
`*_seed*` runs. `RUN_CALIBRATION` stays `False` in the committed notebook.

The text quotes results of the run. After a re-run, check these places against the new outputs:

| Where | What it quotes |
|---|---|
| 0.3, Part 3 (stage table and run cell), B.4, B.7, 5.6 | run times (idle-machine values) |
| 2.2 table | neurons, synapses, memory at the default size |
| 4.4 | the shape of the LFP proxy spectra (Figure 4.5) |
| B.5 | amyloid-vs-CN rate change, full-scale rate estimates, mean DC current onto E populations |
| B.6 | the description of Figure B.6 |
| `tutorial_CN.py` (printed in Part 2) | scan values and rate means of section 4 |

The DC currents are in the network dumps:
`pd.read_pickle("results/<run>/<net_hash>/dc_drive.pkl")` (pA per population).

### 5.3 Re-rendering the full-scale figures

Part 6.2 shows three full-scale runs - `sub007_L`, `sub016_L`, `sub011_R`, one hemisphere each of
three participants of the THU glioma cohort, 10 s each, every parameter identical except the
person's own connectome. The notebook only shows `figures/fullscale/<run>/*.png`;
`tools/make_fullscale_figures.py` renders them, and writes the numbers the text quotes to
`numbers.json`. It needs the runs themselves, imported exactly as the server's Snakemake workflow
wrote them, so the hashes still name their directories (shown for `sub007_L`):

```
fullscale/experiments/sub007_L.py                                     the experiment file
fullscale/experiments/sub007_L.{network,simulation,analysis}_hash
fullscale/out/<net_hash>/<sim_hash>/<ana_hash>/                       all three levels, spikes included
fullscale/logs/sub007_L_*                                             the Snakemake rule logs
fullscale/experimental_data/thu-glioma/thumatrix/sub007_L.npy         the person's BOLD, under its server path
```

To add or replace a run: copy its experiment and hash files into `fullscale/experiments/` under the
run's name, its `<net_hash>/` tree into `fullscale/out/`, and the BOLD file its `ana.yaml` names into
`fullscale/experimental_data/` under the same relative path; add it to `RUNS` in
`tools/make_fullscale_figures.py`, run the script in the `nest3.8` environment, check the numbers
the Part 6.2 text quotes against `numbers.json`, and commit `figures/fullscale/`. Only the rendered
figures are committed; `fullscale/` never is.

### 5.4 Refreshing the model snapshot

`model/` is a copy, not a submodule: it does not follow upstream HuMAM. To take upstream fixes,
copy the source and data over again and re-apply the local changes (section 7), then recalibrate
(5.1) and re-run the notebook (5.2).

## 7. Local changes against the HuMAM snapshot

Commit `de56fac` (base version, 2026-09-18) holds the model as it was copied in;
`git log de56fac..` shows everything since. In short:

- **Neuron types** (`helpers/neuron_types.py`, `network.py`, `simulation.py`): any number of named
  types replace a fraction of every population (scalar, per-area, per-layer or CSV ratios); each
  population is created as contiguous GID blocks per type (`neuron_type_GIDs.dat`), and types with
  their own synaptic time constants get their own DC current (`dc_drive_types`). This replaces the
  earlier `Abeta_*` parameters, which now raise an error.
- **Downscaling** (`network.py`): the DC compensation uses the full-scale mean input computed from
  `fullscale_rates`, with the receiving neuron's synaptic time constants and the realised
  (rounded) in-degrees.
- **Analysis** (`analysis.py`): kernel and NEST-current LFP proxies (the Mazzoni et al. 2015
  reference weighted sum on the excitatory populations), area-level LFP, band-averaged coherence
  (500 ms Welch segments, 0.01-80 Hz by default), n:m theta-beta PLV, FC scored against the
  reference `ana_params["experimental_fc"]` selects (group data or one subject), NaN-safe
  correlations, neuron-type rasters, per-category plot folders. Results that depend on analysis
  parameters are cached per analysis (`<ana_hash>/`), only simulation-level files next to the
  spikes; per-neuron statistics include the neurons that never fired.
- **Theory** (`theory/rates.py`): the mean input includes the DC current and `p_transmit`.
- **Simulation** (`simulation.py`): optional `sim_params["external_weight_sd"]` (section 8).
- **Defaults** (`default_*_params.py`): long-range gains 2.5 / 5.0; `neuron_types`; coherence
  defaults.
- **Removed**: the paper-figure scripts (`figure_*.py`), `snakemake_archive.py`, the Abeta
  population code in `cytoarchitecture.py`.
- **New**: everything in `tools/` and `experiments/`.

## 8. Known issues

What a code review found and is still open. The defects it found are fixed (the history from
`92cd3da` on); the points below are properties of the model or limitations to keep in mind.

- *Downscaled working point.* In `tutorial_CN` 66 of 254 populations, and the excitatory
  populations of several whole areas, are silent; 57 % of all neurons never fire in the 4 s run.
  This is the calibrated downscaled network, not an analysis artefact; the per-neuron statistics
  count these neurons as zeros.
- *Amyloid vs CN is not a clean comparison when downscaled.* Each experiment's DC current comes from
  its own full-scale rates, so the two runs differ in more than the neuron substitution (B.5).
- *External drive heterogeneity.* Each neuron receives its external input through one connection
  with one random weight. With the default `sim_params["external_weight_sd"] = "per_neuron"` the
  mean external drive differs by `PSP_rel` (10 %) between neurons, ~12.5 mV at `eta_ext` 5;
  `"per_synapse"` gives the spread of `K_ext` independent synapses (s.d. / sqrt(K_ext)). The
  calibration of section 4 holds for the default only: switching needs 5.1 and 5.2.
- *Mean-field theory.* `theory/rates.py` includes the DC current and `p_transmit`, but uses the
  base neuron parameters for every population: custom neuron types are not modelled (a warning names
  them). `oscillation_spectrum` needs one `tau_m` and one `tau_s` for the whole network.
- *LFP proxy.* The reference weighted sum (Mazzoni et al. 2015) is implemented as published - input
  onto excitatory populations, AMPA(t - 6 ms) - 1.65 GABA(t) with GABA negative - but its delay and
  weight were fitted to the network and morphology of that paper; here they are an assumption. The
  kernel method has no external input (a constant-rate drive, which drops out in the z-score).
- *Notebook outputs.* The fixes from `92cd3da` to `378a572` change no simulated number, but they
  change analysis outputs: the LFP proxy (its sign flipped - correlation -0.98 with the old one;
  spectra, coherence and the 3:1 PLV are nearly unchanged), the per-neuron rate distributions
  (silent neurons included) and the FC figure (window from `plotConnectivities.tmin`). Re-run the
  notebook (5.2) before distributing it.
- *Old analysis caches.* Analyses made before `3fc14d9` cached their analysis-dependent results in
  the simulation folder. The readers in `tools/pipeline.py` fall back to that location, which is
  right for the imported full-scale runs but would pick up a stale file of an old laptop run.
